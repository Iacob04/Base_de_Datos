--- FASE 2: TEORIA ORAL ---

- Redis es ideal para alta concurrencia porque trabaja en memoria RAM
  (microsegundos de latencia). Ideal para cache, colas y rankings.

- Redis vs MySQL:
  Redis -> en memoria, clave-valor, ultra rapido, sin relaciones
  MySQL -> en disco, relacional, SQL, mas lento para lecturas masivas

4. Ver ayuda en mongosh:

   db.help()

--- FASE 2: TEORIA ORAL ---

- MongoDB vs MySQL:
  MongoDB guarda documentos JSON sin esquema fijo, cada documento
  puede tener campos distintos. Ideal para catalogos donde cada
  producto tiene atributos diferentes.

- Agregacion vs tabla SQL:
  aggregate es un pipeline (filtra, agrupa, calcula) similar a
  SELECT+GROUP BY+JOIN pero sobre documentos JSON flexibles.
  En SQL trabajas con tablas fijas; en MongoDB con colecciones flexibles.

--- FASE 3: OPERACIONES PRACTICAS ---

-- Seleccionar base de datos --
use tienda

-- Insertar documento con estructura anidada (arrays + subdocumentos) --
db.experiencias.insertOne({
  nombre: "Alexis",
  edad: 20,
  habilidades: ["MongoDB", "Redis", "MySQL"],
  direccion: {
    ciudad: "Madrid",
    pais: "Espana"
  },
  activo: true
})

-- Consultas con operadores complejos --
db.experiencias.find({ edad: { $gt: 18 } })
db.experiencias.find({ habilidades: { $in: ["MongoDB", "Redis"] } })
db.experiencias.find({ nombre: { $regex: "^Al", $options: "i" } })

-- Proyeccion (limitar campos devueltos) --
db.experiencias.find({}, { nombre: 1, habilidades: 1, _id: 0 })

-- Actualizar sin sobrescribir --
db.experiencias.updateOne(
  { nombre: "Alexis" },
  { $set: { edad: 21 } }
)
db.experiencias.updateOne(
  { nombre: "Alexis" },
  { $push: { habilidades: "Docker" } }
)

-- Eliminar documento --
db.experiencias.deleteOne({ nombre: "Alexis" })

--- CIERRE ---

docker compose down
